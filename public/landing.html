How it works — 5 steps
1

Ingest PDFs (or JSON)

Feed it lab result PDFs from any lab, in French, English, or German. Tesseract OCR extracts text and bounding boxes at 300 DPI. No PDFs? Pre-extracted JSON works too.

2

Verify patient identity

Each document is checked for name, date of birth, and patient ID. If two PDFs belong to different patients — hard stop, no fallback. One patient per case, enforced.

3

Normalize everything

Analyte names like "Hämoglobin", "Hémoglobine", and "Hemoglobin" all map to one canonical name via a 304-entry multilingual dictionary. Units are converted (g/L → mg/dL). Reference ranges are parsed from the source.

4

Assign panels & compute flags

Each analyte is placed in a clinical panel (blood count, renal, liver, lipids, etc.). Values are compared against reference ranges — red if low, blue if high. No reference range? No color. No guessing.

5

Render the cockpit

Everything is merged chronologically and rendered as a single self-contained HTML file. Parameters as rows, dates as columns, collapsible panels, evidence attributes for traceability. No JavaScript, no server, no external dependencies.

What you see in the output

Each panel is a table. The left column shows the analyte name, unit, and reference range. Each column to the right is a blood draw date. If a value is outside the reference range, it's colored. If no data exists for that date, you see an em-dash (—).

What you will NOT see: statistics, trend arrows, risk scores, clinical interpretation, "improving" or "worsening" labels, patient names in the body. The philosophy: show the clinician the data, let the clinician decide.

Low (below reference) High (above reference) Normal (within range) No data (em-dash)
